# Empower custom-field training project

The training library remains the source of truth. A public no-login web app, **Empower CF Studio**, lives under `web/` and packages the skill for Vercel + OpenAI chat. Continue teaching fields into the skill/MEMORY; the public chatbot is **read-only** against packaged knowledge and must not auto-write lessons from public chats. When changing library content that the site should serve, keep `skills/empower-custom-fields/` updated so `web` sync-knowledge picks it up on build.

At the beginning of relevant work, read MEMORY.md and skills/empower-custom-fields/SKILL.md, then the referenced field records needed for the request. For fields from Custom_Field_F1.xlsx, start with skills/empower-custom-fields/references/custom-field-f1-analysis.md and use its catalog/source links. For how Empower Amount is calculated on this site and why assay/impurity fields multiply Amount by Dilution_Factor and Standard_Potency, read skills/empower-custom-fields/references/amount-empower.md. For assay and Dilution_Factor, read skills/empower-custom-fields/references/assay-single-area.md. For percentage known impurity (workbook vs external impurity standard, labels S1/U1, Peak Labels K/U/M), read skills/empower-custom-fields/references/percentage-known-impurity.md. For the working five-point bracketing-standard %RSD pattern, read skills/empower-custom-fields/references/bracketing-rsd.md. For the working 2489 UV maximum-wavelength fields, read skills/empower-custom-fields/references/uv-wavelength-maximum-2489.md. For the draft five-level mean Response and Pearson r pattern, read skills/empower-custom-fields/references/std-level-mean-correlation-r.md. For general Empower field design, functions, or intersample syntax, start with skills/empower-custom-fields/references/guide-source-map.md and follow its topic links. This project-local skill is explicitly loaded through these instructions; it is not installed globally.

For each new lesson, preserve the original formula and source, update the relevant field record, and update MEMORY.md with confirmed conventions and unresolved questions. Keep detailed knowledge in the skill references so that the skill folder can later be supplied to an application. Record dated corrections and retain superseded formulas with their status rather than silently replacing evidence.

Distinguish user-provided information, user-confirmed conventions, assistant interpretations, arithmetic checks, and Empower-tested evidence. Earlier ChatGPT answers are not independent evidence. Never label a formula validated merely because it was pasted or described as validated by an assistant.

Treat the December 2018 Empower 3 training deck and its extracted references as Waters training-guide evidence. It can establish what the guide taught, but it does not prove behavior in the user's installed Empower version or site configuration. Preserve conflicts within the guide and ask for the intended requirement or an observed Empower result when a conflict affects a generated field.

Treat Custom_Field_F1.xlsx and its extracted references as user-provided workbook definition evidence. Exact rows can establish supplied names, types, defaults, required flags, and formulas. Inferred families and acronym meanings require confirmation. The workbook does not by itself establish missing wizard settings, processing order, observed results, or Empower-tested status.

Use plain language. Ask focused questions about missing information that affects the calculation. Do not invent Empower syntax, defaults, configuration, units, or test results. Do not assume a local convention applies to every Empower installation. No daily background updates are configured: update these files when the user provides a lesson in this project.
